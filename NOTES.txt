API review
---

- Is the API right if designed from scratch? Compare names and signatures
  with other libraries, in Haskell and other languages.
- Are the modules consistent? Is every behavior difference noted in the
  docs? Is all the common functionality in the portable module?
- Renames: setFollowSymLinks => setFollowRootSymlinks (leaves
  setFollowSymLinks for links under the root), isEventsLost =>
  isOverflowEvent, setCreated => reportCreated, isRootUnwatched.
- Should IO be MonadIO?
- Mark /Portable/, /Linux only/ etc. on all APIs.
- Linux: do not scan moved-in dirs by default (setScanNewDirs), macOS and
  Windows do not; then make it a common option.

Features
---

- Watch a non-existing path on Linux and Windows: watch the last existing
  component, add a watch on the next one when it appears. Add to
  design-issues.
- List-and-watch, like tail for listings: scan the tree, then watch.
  lsTail/findTail: report the n newest entries (topBy/bottomBy during the
  scan), then the new ones.
- macOS/Windows: thread-safe watch operations and dynamic add/remove of
  roots through a Watch handle, no command stream (Linux: see
  dev/design-issues/dynamic-watches.md).
- Rescan, to add dirs whose permissions changed; optionally on ATTRIB
  changes.
- Add to watch by pattern, or leave it to find + add.

Linux scans
---

- Use wide DFS always instead of as a fallback? Cost in the common case?
- Concurrent scans, especially the initial one, for a quick start on large
  or cold-cache trees. Other limits may hit first; how many subdirs can a
  watch have?
- Does the order of the scan events (pre or post) matter to users?

Upstream streamly
---

  traversal so it can be used here directly.
